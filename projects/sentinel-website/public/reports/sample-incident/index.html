Sample Incident Record

An example of how a Gatekeeper event can be summarized for review

This is a simplified example showing the format and level of specificity expected in a Sentinel incident summary.

Incident summary

  • Event type: Policy violation
  • Severity: High
  • Disposition: Blocked and held for review
  • Observed at: 2026-03-22 21:25 UTC
  • Source: gatekeeper/sentinel
  • Related rule: Rule R5

Observed

A response under review contained an auth-token value in assistant output. The event was flagged as a credential-exposure risk and the exchange was held pending operator review.

Evidence references

  • Witness entry hash: 055609d94aff159d7e88d55987202b5512dbfcc3692d2e9a2937ee2ead6d5236
  • Artifact reference: gatekeeper-log/2026-03-22-lab.jsonl
  • Rule reference: rule-R5

Control action

  • outbound flow interrupted
  • exchange marked for review
  • event preserved in witness log
  • follow-up remediation required before continuation

Reviewer notes

This example illustrates the intended reporting style:

  • specific
  • time-bounded
  • source-attributed
  • linked to a rule or policy decision
  • clear about what action was taken

It is not meant to expose private customer material. Public examples remain sanitized while preserving the reporting structure.
