Sentinel Gatekeeper

A policy-aware control point that monitors agent exchanges, applies explicit rules, and preserves evidence for review.

Core function

Sentinel Gatekeeper sits at the trust boundary between systems and evaluates requested actions against explicit policies. When activity falls outside the approved lane, Gatekeeper can pause execution, annotate the record, and route the event for operator review.

Operating principles

  1. Explainable enforcement. When an action is blocked or held, Gatekeeper records the relevant rule and the reason it applied.
  2. Measured intervention. Controls are designed to reduce risk without unnecessarily disrupting legitimate work.
  3. Defensible records. Decisions are logged with timing, source, and context for later audit and remediation.

Deployment modes

  • Local node: runs beside a primary workspace and pairs with trusted agents
  • Remote node: extends the same policy boundary to external servers or devices
  • Restricted environment: supports low-connectivity or tightly controlled deployment patterns

Typical use cases

  • onboarding a new agent or integration
  • monitoring high-risk workflows
  • watching for prompt injection, credential requests, or policy drift
  • preserving incident records for review

Status: Private alpha with manual provisioning by the core team.
